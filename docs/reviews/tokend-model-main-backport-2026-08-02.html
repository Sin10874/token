安全上线顺序

  1. 再次确认 PR base 为最新 main；停止写入并用 SQLite .backup 生成可恢复备份。
  2. 部署后端代码；启动时自动执行幂等 schema / catalog / backfill。
  3. 只读核对五个版本行、区间无重叠、四个 flat 行、backfill 数量与 Kimi 拒绝条件。
  4. 运行 ingestion smoke，再部署同 commit 的前端静态构建；观察聚合成本。
  5. 失败时先回退代码，防止重启重放迁移；再执行 rollback SQL。要求字节级恢复时直接恢复上线前 DB 备份。
