发布前置门与顺序

  1. 先由 product owner 在 active cost 与 full billable cost 二选一；按所选口径接线四个 helpers、补 routes 合同并让 ingestion 全量文件真实执行。否则停止上线。
  2. 另开安全迁移完成 React Router 7.18 与 Vite 8.2/plugin-react 6（含浏览器导航、Windows dev-server 与生产构建回归），或由发布 owner 书面接受剩余 4 项风险；本 PR 不猜测。
  3. 两门都绿后再发布 tokend-cli@2.5.1；推送时跳过会写外部版本表的本地 hook，本 PR 不做外部写。
  4. 只读核验 Supabase migration history、当前 active/previous catalog、preflight 聚合与 catalog hash。
  5. 应用 202608020001_model_catalog_refresh.sql。它只安装不可变目录并替换计价函数，不激活新目录。
  6. 用既有 rollout 工具依次 create → freeze → backfill → reconcile；所有 gate 绿后才 activate 2026-08-02。
  7. 观察 unpriced share、Kimi bucket warnings、总成本与供应商报告成本差异；最后再重部署需要该版本的本地 server/UI。

需要：CLI npm 2.5.1、Supabase migration、受控历史 backfill/activation、本地 server/UI 新包。不需要：新的 Supabase Edge Function 或 AI798 页面代码用于这条定价链。

  • 激活前：保持旧 active pointer，不删除已安装目录。

  • CLI：停止分发 2.5.1 / 回退 2.5.0。数据库函数不做破坏性 down migration；如函数需回退，走审阅后的 forward-recovery migration。
